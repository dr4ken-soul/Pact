# Pact Proof-led Submission and Marketing Guide

**Status:** planning only. Do not publish claims until a live demo proves them.

## Voice

- Builder voice, not company voice.
- One clear idea per post.
- Short lines with natural rhythm.
- Use lowercase for social posts if it suits the channel.
- Show what works. The demo carries the story; copy supports it.
- Avoid hype, generic claims, unsupported metrics, and overexplaining the idea.

## Core narrative

AI payment authority should be narrower than a wallet. Pact is testing whether an agent's BCH payment can be bounded by an amount, an approved recipient, and an expiry, with the actual enforcement layer shown honestly.

## Public proof required before posting

- A recorded or live flow showing the policy bounds.
- A real BCH Mainnet transaction through the app with user review and approval.
- A real transaction receipt or explorer link.
- Evidence of WizardConnect integration.
- A clear explanation of which conditions are contract-enforced and which are not.
- A public repository and completed Widget Factory deck.

Do not state that a policy is on-chain enforced until its exact contract behavior is tested. Do not include fake transaction feeds, simulated balances, made-up adoption figures, or unverified security claims.

## Hackathon demo video

Target 60 to 90 seconds:

1. Open the live Pact app and show the rule editor.
2. Show the cap, recipient, expiry, and network.
3. Connect through WizardConnect.
4. Review the exact payment and fee.
5. Approve it in the wallet.
6. Show the actual transaction result.
7. Briefly show the XO template or contract test proving the stated boundary.

Keep a clear Chipnet fallback, marked as Chipnet. Never present a video as if it were a live transaction.

## Submission package

- Live app URL.
- Source repository URL.
- Completed Widget Factory presentation URL.
- Project-controlled EMBER2026 CashTokens address.
- Short, direct product description.
- Demo video or screen recording if useful.
- BLAZE roll-call status and optional community introduction, following current organizer guidance.

The build agent must guide the user through obtaining these values using the direct action links and steps in `BUILD_GUIDE.md`.
